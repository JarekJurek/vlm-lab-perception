# Dataset Datapoint Counts

Counts were generated from `src/tlg/dataset_prompts.yaml` using `scripts/count_dataset_datapoints.py`.
One datapoint is one standardized `TLGAnnotation`, matching the unit evaluated by `run_vlm_tasks.py`.

Source JSON: `results/dataset_datapoint_counts.json`

## Methodology

A datapoint is a single task-level annotation generated by the dataset loader. In
practice, this means one image or sample can contribute more than one datapoint:
for example, a LabLiquidVision sample can produce separate annotations for fill
percentage, fill ordinal level, capacity, container type, liquid color,
grounding, and container count. Conversely, a raw sample can contribute zero
datapoints when the loader filters out all enabled annotations, such as DTLD
samples removed by the default occlusion filtering.

The counting script uses the same prompt assignment source as evaluation:
`src/tlg/dataset_prompts.yaml`. It loads that file through `PromptBank`, builds
the repository dataset loaders, iterates every sample, validates that
`sample["annotations"]` contains standardized `TLGAnnotation` objects, and then
counts each annotation by its task metadata. Dataset totals are therefore sums of
task annotations, not raw image counts, raw object counts, or the length of the
dataset object alone.

The per-dataset-per-task table is the most direct view of the counting process:
each row is the number of annotations emitted for that dataset/task pair. The
per-dataset totals sum those rows within a dataset, while the per-task totals sum
the same task across all datasets where it is enabled.
